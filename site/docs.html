Docs

Everything is one Go binary + Postgres. No build step, no Kafka. Here's how to run it, drive it from an AI agent, and integrate the SDKs.

quickstart

See it prove itself in 60 seconds

go run ./cmd/smolbill quickstart

Seeds a real account — a Pro plan, usage events, and a finalized invoice — and serves it, printing clickable links to the dashboard, the reconciliation ledger, live usage with time-travel (?as_of=), and the AI sandbox (/v1/invoices/simulate). No account, no config.

install

Three ways to get it

# 1. install the binary with Go go install github.com/Arjun0606/smolbill/cmd/smolbill@latest # 2. the whole stack — Postgres + engine docker compose up --build # 3. or grab a prebuilt release binary from GitHub

The Postgres schema self-applies on first connect — no migrate step. Set DATABASE_URL to point at Postgres; leave it unset for an in-memory dev store (not persisted).

rest api

A small /v1 surface

MethodPathWhat it does
POST/v1/customerscreate a customer
POST/v1/metersdefine a meter (count · sum · max · unique)
POST/v1/plansversioned plan + prices
POST/v1/subscriptionsattach a plan to a customer
POST/v1/eventsidempotent usage ingest (dedup on idempotency_key)
GET/v1/usage/{customer}live usage + projected bill — add ?as_of= to time-travel
POST/v1/invoices/simulatesandbox — replay real usage against a proposed plan, persists nothing
POST/v1/invoices/finalizematerialize invoice + persist the reconciliation ledger
GET/v1/reconcile/{invoice}the proof — 200 consistent / 409 + diff if it drifted
GET/v1/invoices/{invoice}/revenuerecognized-vs-deferred split (ASC 606)
POST/v1/gatereal-time allow/deny — block at the limit or at balance=0
GET/v1/entitlements/{customer}real-time limit check (live usage, not a counter)
POST/v1/wallet/{customer}/topupidempotent prepaid wallet credit

Money math is integer-precise decimals (never floats) and rounds toward under-billing. The REST API and the MCP server compute through one shared engine, so a human and an agent can never get different numbers.

ai / mcp

Drive your billing by talking to an agent

smolbill speaks MCP. Over stdio for local editors — Claude Code, Cursor, Cline, Windsurf, Zed — and over Streamable HTTP for remote clients like ChatGPT and claude.ai connectors. The HTTP transport serves on /mcp and negotiates the protocol version by echoing the client's requested revision.

# local editors — stdio transport smolbill mcp
# remote clients — Streamable HTTP on /mcp smolbill mcp --http

Tools are intent-only — there is deliberately no charge() or calculate_bill(). The agent passes intent (attach_plan, record_usage); the deterministic engine does every cent. A test asserts no money-math tool can ever be exposed.

sdks

TypeScript & Python

# TypeScript npm i smolbill const sb = new Smolbill({ baseUrl: "http://localhost:8080" }); const cus = await sb.customers.create({ name: "Acme AI" }); const proof = await sb.invoices.reconcile(invoiceId);
# Python pip install smolbill sb = Smolbill(base_url="http://localhost:8080") cus = sb.customers.create(name="Acme AI") proof = sb.invoices.reconcile(invoice_id)

Both SDKs are Apache-2.0, so your app can integrate the client freely — no copyleft obligation. They're snake_case 1:1 with the wire and ship typed, signature-verifying webhook handling.
